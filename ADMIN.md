# Панель контенту — ShoSho Trip

Панель живе за адресою **`/admin`** на самому сайті (наприклад
`https://shoshotrip.com/admin`). Через неї можна створювати й редагувати
**тури**, **команду** та **відгуки** — без розробника і без бази даних.

---

## Як це працює

Сайт статичний: на хостингу лежать готові HTML-файли, там немає ні сервера, ні
бази. Тому панель влаштована так:

```
Ви редагуєте у /admin
        ↓ «Зберегти»
Зміни зберігаються в репозиторій GitHub (це і є сховище)
        ↓ автоматично, ~2 хвилини
GitHub перезбирає сайт і заливає його на Hostinger
        ↓
Зміни видно відвідувачам
```

Через це **між «Зберегти» і появою змін на сайті проходить приблизно дві
хвилини**. Це нормально, не потрібно зберігати повторно.

Побічний, але корисний ефект: кожне збереження — це запис в історії з датою й
автором. Будь-яку зміну можна подивитися або відкотити.

## Разове налаштування

### 1. Токен доступу для редактора

Кожен, хто редагує сайт, отримує власний токен. Робиться один раз.

1. Зайдіть на GitHub під своїм акаунтом.
2. Відкрийте **Settings → Developer settings → Personal access tokens →
   Fine-grained tokens → Generate new token**.
3. Заповніть:
   - **Token name** — наприклад `ShoSho admin`
   - **Expiration** — 90 днів або довше (після закінчення токен доведеться
     створити заново)
   - **Repository access** → *Only select repositories* → оберіть репозиторій
     сайту
   - **Permissions → Repository permissions → Contents** → **Read and write**
4. Натисніть **Generate token** і **скопіюйте його одразу** — вдруге GitHub
   його не покаже.
5. Відкрийте `/admin`, вставте токен, натисніть «Увійти».

Токен зберігається лише у вашому браузері. Він не потрапляє на сайт і не
видимий відвідувачам. На чужому комп'ютері — натискайте «Вийти».

> Токен дає право змінювати вміст репозиторію. Не пересилайте його в
> месенджерах і не зберігайте у спільних документах.

### 2. Автоматична збірка й викладка

У репозиторії на GitHub відкрийте **Settings → Secrets and variables →
Actions** і додайте секрети:

| Ім'я | Значення |
|---|---|
| `FTP_SERVER` | FTP-адреса хостингу, напр. `ftp.shoshotrip.com` |
| `FTP_USERNAME` | FTP-користувач |
| `FTP_PASSWORD` | його пароль |
| `FTP_DIR` | тека сайту, зазвичай `/public_html/` |

На вкладці **Variables** можна додати `NEXT_PUBLIC_SITE_URL`,
`NEXT_PUBLIC_ADMIN_REPO`, `NEXT_PUBLIC_ADMIN_BRANCH`.

Сам процес описано у [.github/workflows/deploy.yml](.github/workflows/deploy.yml).
Після цього кожне збереження з панелі автоматично оновлює сайт. Стан збірки
видно на вкладці **Actions**.

## Робота з панеллю

Угорі три розділи: **Тури**, **Команда**, **Відгуки**. Зліва — список записів,
справа — форма.

- **Додати** — створює новий запис.
- **Зберегти** — вгорі праворуч. Кнопка активна лише коли є зміни.
- **Видалити** — у формі запису.
- Якщо є незбережені зміни, панель попередить перед виходом.

### Дві мови

Сайт працює українською та англійською, тому текстові поля показані парою:
**Українською** і **English**. Заповнюйте обидва — англійська версія сайту бере
текст саме з правого поля. Якщо його лишити порожнім, у англійській версії
буде порожньо.

### Фото

Біля кожного поля з фото є кнопка **Завантажити файл**. Файл потрапляє в
репозиторій (`public/media/uploads/`), а в поле підставляється шлях.

Кілька практичних порад:

- Фото стискайте **перед** завантаженням. Знімок із телефона на 5 MB зробить
  сайт повільним. Розумний орієнтир — до 500 KB, ширина 1600 px.
- **HEIC із айфона не підійде** — браузери його не показують. Зберігайте як
  JPEG.
- Вертикальні й горизонтальні фото обрізаються під формат блоку, тому головне
  тримайте по центру кадру.

### Тури

Найважливіші поля:

- **Адреса сторінки** — частина посилання (`/ua/tours/morocco-atlas`).
  Заповнюється автоматично з назви, якщо лишити порожнім. **Після публікації
  краще не змінювати** — старі посилання перестануть працювати, а сторінка
  втратить позиції в пошуку.
- **Дата початку** — у форматі `2026-11-14`. За нею тури сортуються на сайті.
- **Програма по днях** — кожен день розгортається натисканням. Усередині опис,
  маршрут, дорога, навантаження, харчування, ночівля і фото дня. Якщо фото дня
  не задати, візьметься кадр із галереї туру.
- **Галерея** — фото туру. Вони ж підставляються дням без власного фото.
- **Демо-тур** — поставте «Ні» для справжнього туру. «Так» позначає зразки для
  верстки.

### Команда

Список людей у блоці «Хто їде з вами». Можна додавати третю й наступних — блок
більше не обмежений двома засновниками.

- **Кадрування фото** — картка обрізає знімок під горизонтальний формат.
  Оберіть, яку частину лишити: для фото на весь зріст зазвичай підходить
  «Верх», для портрета — «Центр».
- **Особиста історія** — необов'язкова. Кожен абзац окремим полем. Якщо
  порожня, кнопка «Читати історію» на сайті не показується.

### Відгуки

Формат відгуку задає, які поля використовуються:

| Формат | Що заповнювати |
|---|---|
| Текстовий | текст, ім'я, фото автора |
| Відео | відео, обкладинка, ім'я |
| Скриншот | скриншот або текст |
| Фото | фото учасника, підпис у полі тексту |

**Instagram автора** заповнюйте тільки якщо людина дозволила посилатися на її
профіль.

**Демо-відгук** — «Так» означає вигаданий зразок. Реальному відгуку обов'язково
поставте «Ні»: інакше справжня людина буде позначена як вигадана.

## Якщо щось пішло не так

| Повідомлення | Що робити |
|---|---|
| «Токен недійсний або прострочений» | Створіть новий токен (розділ 1) і збережіть його ще раз. |
| «Токен не має права на запис» | У налаштуваннях токена увімкніть **Contents: read and write**. |
| «Файл змінився з моменту завантаження» | Хтось редагував паралельно. Перезавантажте сторінку і внесіть правку заново. |
| «Дві однакові адреси сторінки» | Два тури з однаковим полем «Адреса сторінки». Змініть одне з них. |
| Збережено, але на сайті нічого не змінилось | Зачекайте 2–3 хвилини. Якщо не з'явилось — подивіться вкладку **Actions** на GitHub: там буде видно помилку збірки. |

## Що панель не змінює

Свідомо лишилось поза панеллю, бо це рідко змінюють і легко зламати:

- тексти головної сторінки, заголовки блоків, меню, підвал — у
  `src/content/dictionaries.ts`;
- загальний FAQ — у `src/content/faq.ts`;
- юридичні документи — у `src/content/legal.ts`;
- галерея «Емоції» — у `src/content/emotionsGallery.ts`;
- контакти й посилання на соцмережі — у `src/content/config.ts`.

Ці файли редагує розробник. За потреби будь-який із них можна додати в панель —
опис полів лежить в одному місці, `src/admin/schema.ts`.
